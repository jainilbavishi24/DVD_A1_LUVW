\section{Introduction}
This report implements a registered, unsigned 4-bit by 4-bit array multiplier and takes it from structural Verilog to a routed GDSII layout. The flow used Icarus Verilog for simulation, GTKWave for waveforms, Yosys for synthesis, OpenSTA for timing analysis, and LibreLane for physical design. Every number below was regenerated with the current IIC-OSIC-TOOLS image (\code{hpretl/iic-osic-tools:latest}, digest \code{sha256:306585de35d1}); the tool versions are listed in Section~\ref{sec:tools}. All generated artifacts, scripts, logs and the final GDSII are included in the repository.

\section{Design and verification (Part A)}
The multiplier registers \code{a[3:0]} and \code{b[3:0]}, forms the 16 partial-product bits $pp_i[j]=a[j]\,\&\,b[i]$, and adds rows 1--3 with exactly 12 instances of \code{full\_adder}, following the connection table of the assignment. Row 0 contributes \code{p[0]}; the lowest sum of each later row is \code{p[1]}, \code{p[2]} and \code{p[3]}, and row 3 also produces \code{p[7:4]}. The combinational result is captured in the 8-bit output register, so there are 16 AND gates, 12 full adders and 16 flip-flops, all with asynchronous active-low reset. An input applied before edge 1 is captured at edge 1 and its product is captured at edge 2, giving a latency of 2 cycles and a throughput of 1 result per cycle.

\begin{figure}[h]
\centering
\includegraphics[width=0.80\linewidth]{array_multiplier_block.png}
\caption{Block diagram: input registers, the 16 AND gates and 12 full adders arranged by bit weight, and the 8-bit output register.}
\end{figure}

The self-checking testbench \code{tb/tb\_mult.v} uses a 10 ns clock, holds \code{rst\_n} low for the first 2 cycles, applies all 256 input pairs, waits for the 2-cycle latency and compares \code{p} with \code{a * b}, printing every mismatch and writing \code{mult.vcd}. It samples \code{p} on the falling edge after the capture edge, which keeps the comparison clear of the flip-flop clock-to-Q update in both RTL and gate-level simulation. RTL simulation reported \code{PASS: 256 vectors checked, 0 errors}. To prove the checker detects errors, \code{sum = a \^{} b \^{} cin} was temporarily changed to \code{sum = a \^{} b}; the test then reported \code{FAIL: 256 vectors checked, 95 errors}, after which the correct RTL was restored.

For the required personal example we used Jainil Bavishi's roll number 2023102045: the last digit is 5, so $A=5+5=10$ and $B=7$. Worked by hand in the partial-product layout:
\begin{verbatim}
        1 0 1 0      A = 10
      x 0 1 1 1      B = 7
   ---------------
        1 0 1 0      pp0 = A AND b0 (b0 = 1)
      1 0 1 0        pp1 = A AND b1 (b1 = 1), shifted 1
    1 0 1 0          pp2 = A AND b2 (b2 = 1), shifted 2
  0 0 0 0            pp3 = A AND b3 (b3 = 0), shifted 3
   ---------------
0 1 0 0 0 1 1 0      P = 70
\end{verbatim}

\section{Static timing analysis (Part C)}
OpenSTA used the typical \code{tt\_025C\_1v80} Liberty corner, a 1.00 ns input delay and a 1.00 ns output delay. At the initial 10.00 ns period the worst setup slack was 7.21 ns, so $T_{min}=10.00-7.21=2.79$ ns and $F_{max}=1000/2.79=358.42$ MHz. Re-running at 2.79 ns gave a worst slack of $+0.003$ ns (0.00 ns at two decimals), confirming the result; at 2.78 ns the slack is $-0.01$ ns.

The critical path, from \code{sta/mult\_array\_timing.rpt}, is
\code{dfrtp\_1} (\code{a\_reg[1]}) $\rightarrow$ \code{clkinv\_1} $\rightarrow$ \code{o311ai\_0} $\rightarrow$ \code{a21oi\_1} $\rightarrow$ \code{maj3\_1} $\rightarrow$ \code{xnor3\_1} $\rightarrow$ \code{maj3\_1} $\rightarrow$ \code{maj3\_1} $\rightarrow$ \code{xor3\_1} $\rightarrow$ \code{dfrtp\_1} (\code{p[6]}), with a data arrival time of 2.652 ns. Its end point is the sum of \code{fa\_r3\_3}, the last adder of row 3. Five of the eight combinational cells are recognisable full-adder functions: the three \code{maj3} cells are full-adder carry outputs and the \code{xnor3}/\code{xor3} cells are full-adder sum outputs. The first three cells (\code{clkinv}, \code{o311ai}, \code{a21oi}) implement partial-product AND gates merged with the simplified row-1 adder logic, whose carry-in and top input are constant 0. The path therefore has 8 combinational cell delays, the same count as the $2N=8$ full-adder-delay estimate. The match is approximate, because each cell implements only the carry or the sum of one adder (or a merged AND), and synthesis does not keep one library cell per full adder.

\section{Physical design (Part D)}
The configuration uses \code{FP\_SIZING = "absolute"} and a fixed \code{DIE\_AREA = [0, 0, 150, 150]}. The required first period is $1.2\times2.79=3.348$ ns, rounded up to 3.50 ns. Table~\ref{tab:runs} lists every attempt; the setup slack is LibreLane's \code{timing\_\_setup\_\_ws}, the worst over all signoff corners. The period was increased by 0.50 ns after each failing run. In every run the limiting corner was the slow \code{max\_ss\_100C\_1v60} corner, while the typical-corner slack was positive in every run (+0.431 ns already at 3.50 ns). Slack did not improve steadily with the period: from 6.00 ns to 7.50 ns it stayed between $-0.04$ and $-0.21$ ns. LibreLane re-runs synthesis, placement and timing repair for each target period, and the buffers it puts on the critical net change with the period: up to 6.00 ns they were fast \code{buf\_4} rebuffers, at 6.50 and 7.00 ns a slow \code{clkdlybuf4s25} delay cell was used as a max-capacitance buffer, and from 7.50 ns a second one was added as a wire buffer. Together the two delay cells add about 1.24 ns at the slow corner. The 7.50 ns and 8.00 ns runs produced the same critical path (arrival 7.64 ns), so the extra 0.50 ns at 8.00 ns turned $-0.138$ ns into $+0.362$ ns. This is why 10 runs were needed, compared with 7 when this design was first implemented with an older tool image.

\section{Answers to questions}
\begin{enumerate}[leftmargin=*,label=\textbf{\arabic*.}]
\item Synthesis produced $61-16=45$ logic cells. This is not simply $16+12=28$ because a full adder is not mapped to one cell: \code{abc} maps each carry to a \code{maj3} or AOI/OAI gate and each sum to XOR/XNOR gates, so one full adder becomes about two to three cells. Many AND gates are not separate cells either; they are merged into NAND, AOI and OAI gates that drive the adders, and the constant-0 inputs of the first adders are simplified away.
\item The critical path starts at input register \code{a\_reg[1]} (\code{\_91\_}) and ends at output register \code{p[6]} (\code{\_88\_}, the sum of \code{fa\_r3\_3}). It has 10 cells: the two flip-flops and 8 combinational cells, of which 5 (\code{maj3} $\times3$, \code{xnor3}, \code{xor3}) are full-adder carry/sum functions and 3 are merged AND/row-1 logic. Its 8 combinational cell delays match the $2N=8$ full-adder-delay estimate for $N=4$ in count, although each cell is only part of a full adder (its carry or its sum), so the agreement is approximate.
\item Flip-flops occupy $400.384/756.976\times100=52.89\%$ of the synthesized cell area. A resettable flip-flop is a large cell: one \code{dfrtp\_1} is 25.02 $\mu$m$^2$, against 3.75 $\mu$m$^2$ for a \code{nand2\_1} and 10.01 $\mu$m$^2$ for a \code{maj3\_1}. The design needs 16 of them, while a 4-bit array has only 45 mostly small logic cells. The register overhead is fixed by the I/O width, so in a tiny datapath it dominates the area.
\item The post-route $F_{max}$ of 130.92 MHz is lower than the 358.42 MHz from Part C because Part C used ideal wires, an ideal clock and the typical corner only. Post-route signoff checks every corner, and the limiting one is the slow \code{max\_ss\_100C\_1v60} corner (the typical-corner slack at 8.00 ns is +4.22 ns). The worst path is the same \code{a\_reg[1]} $\rightarrow$ \code{p[6]} adder chain as in Part C, but it now arrives at 7.64 ns. At the slow corner every cell is about 2--2.5$\times$ slower (the flip-flop clock-to-Q alone grows from 0.40 to 0.99 ns), and two delay-cell repair buffers add 1.24 ns. The clock tree adds 0.57 ns of insertion delay at the launch flip-flop, but this is largely cancelled by 0.51 ns at the capture flip-flop. On the required side, 0.25 ns of clock uncertainty and a 0.29 ns slow-corner setup time are subtracted. Wire delay itself is small on a 150 $\mu$m die. The flow added 1,299 decap cells and 254 filler cells to fill the empty row space, continuing the power rails and wells; the decaps also add local supply decoupling capacitance. 245 tap cells tie the n-well and substrate to VPWR/VGND to prevent latch-up. 21 timing-repair buffers (17 \code{buf\_2} and 4 \code{clkdlybuf4s} cells) fix maximum slew, capacitance and wire-length limits on long or heavily loaded nets. 3 \code{clkbuf\_16} clock buffers form the clock tree that drives all 16 flip-flops with low skew.
\item DRC checks that the drawn layout obeys the foundry's geometry rules (minimum width, spacing, enclosure, density and so on), so it can be manufactured reliably. LVS extracts the transistors and connectivity from the layout and compares them with the intended netlist, so it confirms the layout is the circuit that was designed. Both must pass: a layout can meet every geometric rule but connect the wrong nets, or have the right connectivity but violate a rule that causes shorts or opens on silicon.
\item For an $N$-bit array, the number of AND gates is $N^2$ and the number of full adders is $N(N-1)$. At $N=8$: $8^2=64$ AND gates and $8\times7=56$ full adders, against 16 and 12 at $N=4$, so the full adders grow by $56/12\approx4.7\times$. The critical path grows from $2\times4=8$ to $2\times8=16$ full-adder delays, so the combinational delay roughly doubles. Scaling our measured path: its combinational part is $2.652-0.398=2.254$ ns, which doubles to about 4.51 ns; adding the 0.398 ns clock-to-Q and 0.135 ns setup time gives $T_{min}\approx5.04$ ns, so $F_{max}$ would drop from 358 MHz to about 198 MHz before layout effects.
\end{enumerate}

\section{Conclusion}
The structural RTL passed exhaustive RTL and gate-level simulation with the assignment's exact commands, and the fault-injection check confirmed that the testbench detects errors. Synthesis produced 61 cells (756.976 $\mu$m$^2$), STA gave $T_{min}=2.79$ ns ($F_{max}=358.42$ MHz), and LibreLane closed timing at an 8.00 ns clock after 10 runs with 0.3618 ns setup slack, 0 DRC errors and 0 LVS errors.
